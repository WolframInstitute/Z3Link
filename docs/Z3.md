# WolframInstitute/Z3

Bindings to the **Z3 theorem prover** (an SMT solver from Microsoft Research) for the Wolfram Language. Enter problems as native Wolfram expressions *or* as SMT-LIB2, and get results translated back into exact Wolfram values (integers, rationals, algebraic numbers, booleans, bit-vectors, functions).

## Installation

The paclet drives the `z3` command-line solver. It looks for `z3` in this order: an executable you set explicitly, the `Z3_PATH` environment variable, your system `PATH`, common install locations, a previously downloaded copy, and finally it **downloads a private copy of z3 automatically** (once) if none is found. So nothing needs to be installed by hand.

```wl
Needs["WolframInstitute`Z3`"]
Z3InstallationLocation[]
```

The first call locates or downloads z3 (printing a one-time progress message). `Z3Version[]` reports the version in use, and `Z3SetExecutable["/path/to/z3"]` forces a specific binary.

## Quick start

Solve a system of integer constraints. Variables are ordinary symbols; the second argument declares their domain, exactly like `Solve` or `Reduce`.

```wl
Z3Solve[x > 2 && y < 10 && x + 2 y == 7, {x, y} \[Element] Integers]
```

`Z3Solve` returns an association mapping each variable to its value when the problem is satisfiable, the symbol `Unsatisfiable` when it is not, and `Indeterminate` when z3 cannot decide.

## Two ways to enter a problem

### Native expressions with a domain (Style 1)

Write ordinary Wolfram boolean and arithmetic expressions and declare the variable sorts separately. Supported domains include `Integers`, `Reals`, and `Booleans`.

```wl
Z3Solve[a || b && ! c, {a, b, c} \[Element] Booleans]
```

### Typed handles (Style 2, z3py-like)

Create typed variable handles and build expressions with normal operators. This is the idiom used by the Python z3 bindings, and it is required where a sort carries parameters (bit-vector widths, array sorts).

```wl
x = Z3Int["x"]; y = Z3Int["y"];
Z3Solve[{x + 2 y == 7, x > 2, y < 10}]
```

Handle constructors: `Z3Int`, `Z3Real`, `Z3Bool`, `Z3BitVec[name, width]`, `Z3Array[name, domSort, rngSort]`, `Z3Const[name, sort]`, and `Z3Function[name, {argSorts}, resultSort]` for uninterpreted functions.

## Exact results

Results stay exact. Rationals come back as `Rational`, and algebraic numbers from nonlinear real arithmetic come back as `Root` objects (which Wolfram simplifies where it can).

```wl
Z3Solve[3 r == 1, r \[Element] Reals]
```

```wl
Z3Solve[s^2 == 2 && s > 0, s \[Element] Reals]
```

Pass `"Numeric" -> True` to get machine-precision numbers instead.

## Theories

### Integers and reals

Linear and nonlinear arithmetic over `Integers` and `Reals`, including `Mod`, `Quotient`, `Abs`, `Min`, `Max`, `Floor`, `Ceiling`, and integer powers.

### Bit-vectors

```wl
a = Z3BitVec["a", 8];
Z3Solve[{a == Z3BitVecVal[10, 8] + Z3BitVecVal[5, 8]}]
```

Arithmetic operators on bit-vector handles map to the bit-vector operations (`bvadd`, `bvmul`, ...). For any other SMT operator use the escape hatch `Z3Op["bvand", a, b]`.

### Arrays

```wl
m = Z3Array["m", "Int", "Int"];
sol = Z3Solve[{Z3Select[m, 2] == 9, Z3Select[m, 5] == 7}];
sol["m"][2]
```

Array models come back as callable pure functions. `Z3Select[arr, i]` and `Z3Store[arr, i, v]` build the array terms.

### Uninterpreted functions

```wl
f = Z3Function["f", {"Int"}, "Int"];
sol = Z3Solve[{f[0] == 5, f[1] == 7}];
sol["f"][0]
```

### Quantifiers

Reuse the Wolfram `ForAll` and `Exists`, attaching sorts to the bound variables with `\[Element]`. (The built-in `ForAll` prints a harmless `ForAll::ivar` message; `Z3ForAll` / `Z3Exists` are message-free equivalents.)

```wl
Z3ProvableQ[ForAll[x \[Element] Integers, x^2 >= 0], {}]
```

## SMT-LIB input and output

Hand z3 a raw SMT-LIB2 script (string or `File[...]`) and get its response back:

```wl
Z3RunSMTLIB["(declare-const a Int)(assert (> a 41))(assert (< a 43))(check-sat)(get-value (a))"]
```

To see the SMT-LIB2 that a native problem produces, use `Z3ToSMTLIB`:

```wl
Z3ToSMTLIB[x > 2 && y < 10 && x + 2 y == 7, {x, y} \[Element] Integers]
```

## Incremental solving

A `Z3SolverObject` keeps a live z3 process with a push/pop assertion stack, exactly like a z3py `Solver`.

```wl
s = Z3CreateSolver[];
Z3Assert[s, x > 0 && x < 10, x \[Element] Integers];
Z3CheckSat[s]
Z3Model[s]
Z3Push[s];
Z3Assert[s, x > 8, x \[Element] Integers];
Z3CheckSat[s]
Z3Pop[s];
Z3Eval[s, x + 1]
```

`Z3CheckSat` returns `"sat"`, `"unsat"`, or `"unknown"`. After an unsatisfiable check, `Z3UnsatCore[s]` returns the conflicting subset of assertions, and `Z3Statistics[s]` returns solver statistics.

## Optimization

z3's optimization engine is exposed through `Z3Optimize` (one-shot) and `Z3Maximize` / `Z3Minimize` on an optimizer object.

```wl
Z3Optimize[x -> Maximize, x > 0 && x < 100, x \[Element] Integers]
```

```wl
o = Z3CreateSolver["Optimize"];
Z3Assert[o, x + y == 10 && x >= 0 && y >= 0, {x, y} \[Element] Integers];
Z3Maximize[o, x*x + y*y];
Z3CheckSat[o];
Z3Model[o]
```

## Options

`Z3Solve` and `Z3Optimize` accept:

- `"Timeout" -> ms` sets a per-solve timeout in milliseconds.
- `"Numeric" -> True` returns machine-precision numbers instead of exact ones.
- `"Options" -> {"name" -> value, ...}` sets arbitrary z3 options.

`Z3SetOption[solver, "name" -> value]` sets options on a solver object directly; every z3 option is reachable this way.

## Convenience predicates

```wl
Z3SatisfiableQ[x^2 == 2, x \[Element] Reals]
```

```wl
Z3ProvableQ[Implies[x > 0, x + 1 > 1], x \[Element] Integers]
```

`Z3ProvableQ[claim, domain]` is `True` when the claim holds for all values of the variables (its negation is unsatisfiable).
